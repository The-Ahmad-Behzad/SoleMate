# Proposal: Open-Source Markerless AR Fallback (Non-ARCore) - Revised Plan

## Problem

Current implementation (`ARActivity.kt` lines 550-554) finishes the activity if ARCore is unavailable, blocking users on non-ARCore devices. `SimpleRenderer.kt` is tightly coupled to ARCore APIs (Session, Frame, Plane, Anchor, HitResult). We need markerless world tracking for virtual shoe try-on without commercial SDKs.

## Current State Analysis

**Existing ARCore Integration:**

- `ARActivity.kt`: ARCore session management, checks availability and exits if unsupported
- `SimpleRenderer.kt`: Uses ARCore Session/Frame for plane detection, hit testing, anchor creation (lines 320-743)
- `FootTracker.kt`: MediaPipe Pose Landmarker - **already independent** of ARCore
- `ShoeRenderer.kt`: Filament-based 3D rendering - **already independent**, just needs view/proj/model matrices
- `BackgroundRenderer.kt`, `PlaneRenderer.kt`: ARCore-specific rendering utilities
- Native infrastructure: `CMakeLists.txt` exists, `native-lib.cpp` is a stub

**Key Dependencies:**

- ARCore 1.46.0 (hard requirement currently)
- Filament 1.65.2 (works with any pose source)
- MediaPipe Tasks Vision 0.10.14 (already independent)

## Recommendation (Dual Path Architecture)

**ARCore Path (keep):** On ARCore-capable devices, continue using ARCore for world tracking, anchors, depth, and lighting.

**Open-Source VIO Fallback:** On non-ARCore devices, implement visual-inertial odometry (VIO) + plane estimation using VINS-Mono (BSD license), fused with foot landmarks for pose/scale.

## How It Works (Fallback Pipeline)

1. Camera + IMU stream → VIO estimates continuous device pose (no ARCore)
2. Floor plane estimation via RANSAC over tracked points near bottom of view; enforce gravity alignment using IMU
3. MediaPipe foot landmarks → 2D ankle/toe; unproject via current camera pose and plane to get 3D foot contact point
4. Shoe pose = plane-anchored transform with forward vector from ankle→toe projected onto plane; scale via calibrated foot length + camera height estimate from VIO
5. Stabilize via exponential smoothing and Mahalanobis gating using VIO covariance; re-anchor on drift

- **Stability**: Walk small circles; verify shoe remains foot-locked within ±3 cm
- **Performance**: FPS target 24+; log VIO update rate and latency
- **Battery**: 10-minute session thermal/battery impact
- **Calibration**: Verify scale accuracy after calibration (measure real vs virtual shoe)

## Risk & Mitigation

- **Integration complexity**: Start with VINS-Mono prebuilt library if available; fallback to minimal VIO implementation
- **Scale ambiguity**: One-time calibration + continuous refinement using foot length (already implemented in SimpleRenderer lines 645-652)
- **Performance on low-end**: Downscale camera to 640-720p for VIO; throttle landmark detection (already throttled, line 336)
- **ARCore regression**: Keep ARCore path fully functional; abstraction layer ensures isolation
